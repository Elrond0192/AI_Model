# Future BB-Rating prediction and scenario calibration

## Objective

The public player timeline must use one meaning of BB-Rating throughout:
- historical seasons: observed BB-Rating calculated by the versioned BB-Rating engine;
- current season: observed BB-Rating, labelled with its context and data status;
- future seasons: predicted BB-Rating whose target labels were generated by the same engine on historical target-season data.

The existing native 0-10 prediction target and its 1-100 presentation calibration are not BB-Rating targets and must not be relabelled as such.

## Scenario dimensions

Every training/evaluation row must retain source and destination:
- player canonical identity;
- source and target season;
- source and target league;
- source and target team;
- competition/phase;
- source BB-Rating and source metric history, available only through the source season;
- target BB-Rating label, calculated in the target league + target season + competition peer context.

Use explicit transition classes: same team/same league, team change within league, league change, and combined team + league change. Do not infer a league transfer solely from a changed team ID.

## Why target-league context matters

BB-Rating is a within-context relative score, not a universal cross-league strength scale. A player's source BB-Rating must not be copied as the target label after a transfer. For each historical target season, calculate the target score using the destination league's official BB-Rating peer population. A predicted score of 75 in two different leagues means strong relative standing in each context, not necessarily identical absolute player quality.

For transfers, features must include source context, destination league/competition and transition type, while all player-performance features must be strictly as-of the source season. Destination team features may be used only if they are genuinely known at prediction time; otherwise they leak future information. Team IDs must not be treated as ordinal numbers.

## Scenario calibration

The module basketball_ai.bb_rating.prediction_scenarios provides an isotonic calibration layer for OOF predictions already expressed on the official 1-100 BB-Rating scale. It fits:
1. destination league + transition scenario;
2. scenario-only fallback;
3. global fallback.

Sparse groups are not fitted. The artifact reports group sample counts and the selected calibration level. Calibration must be trained on walk-forward out-of-fold predictions, never in-sample predictions. The global fallback is for numerical stability, not evidence that league contexts are interchangeable.

## Required promotion gates

This utility is not yet wired into production and does not itself generate BB-Rating targets. Do not activate it as a player-facing prediction until the end-to-end model work is complete:
1. generate historical BB-Rating labels with the pinned BB-Rating engine version and destination context;
2. retrain the existing prediction path against those labels, and replace native 0-10 clipping, persistence assumptions, uncertainty intervals and contracts with 1-100 semantics;
3. use expanding walk-forward folds by target season; fit scenario calibration only on earlier OOF predictions;
4. report MAE, RMSE, bias and calibration error separately for each transition class and destination league;
5. compare against target-context persistence and a simple league/scenario baseline;
6. fail closed or return an explicit low-support status when transfer cohorts are too small;
7. keep old artifacts and API contracts available for rollback until all gates pass.

A scenario-calibration layer cannot repair a target mismatch, leakage, missing transfer examples, or a model that predicts the wrong target. It only corrects systematic mapping errors in valid OOF BB-Rating predictions.
